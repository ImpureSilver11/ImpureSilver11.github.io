# new-post: ブログ記事の新規作成 + 草稿執筆

## 引数
- `$ARGUMENTS`: 記事のテーマ・タイトル案（日本語でOK）。ファイルパスが含まれていればコードを読む。

## 前提

**執筆前に `.claude/templates/writing-style.md` を必ず読む。** 口調・文体・AIっぽさの排除・自己チェックのルールはすべてそこに定義してある。このスキルは記事作成のワークフローだけを扱う。

MDX の使える記法（`<Callout>` / `<YouTube>` / `<LinkCard>` / GFM など）は `README.md` を参照する。

## 手順

### 1. ファイル名を決める
- 今日の日付と時刻を `date` コマンドで取得する（`date +%Y-%m-%d` と `date +%H-%M-%S`）
- `$ARGUMENTS` を英語のkebab-caseに変換してスラグを作る
  - 例: "Claude Codeを使い始めた話" → `claude-code-getting-started`
  - 英語に意訳してよい。直訳でなくて構わない。短く端的に。
- ファイルパス: `posts/YYYY-MM-DD-HH-MM-SS-{slug}.md`

### 2. 事前調査（引数にパスが含まれる場合）
- `$ARGUMENTS` に絶対パスまたは相対パスが含まれていれば、そのディレクトリを探索する
- `find {path} -type f | grep -v '.git'` でファイル一覧を把握する
- 主要なソースファイル（README、メインの実装ファイルなど）を読んで内容を把握する
- 把握した内容を草稿に反映する

### 3. 不明点・体験談のヒアリング（草稿を書く前に必ず実施）

**この記事は本人の体験として公開される。** だから体験・数値・感想を推測で埋めてはいけない。書き始める前に、`AskUserQuestion` で3〜4問まとめて聞く。

必ず確認する（会話や事前調査から確定していないもののみ）:
- **構成**: どの順で何を扱うか。特に「どこを厚く書くか」「触れなくていいトピック」
- **実体験**: いつ・どこで・何をして・何が起きたか。ハマった箇所、所要時間、実際のエラーメッセージ、ビフォーアフターの数値
- **感情の温度感**: 楽しかったのか、しんどかったのか、途中でやめたくなったのか。どこが一番きつかったか
- **公開して問題ない範囲**: 社名・案件名・顧客名・社内固有の構成など、伏せるべき情報がないか
- **結論**: 本人としてどういう立場か（採用した／見送った／保留中）
- **参考にしたもの**: 読んだ書籍、見た記事・公式ドキュメント・動画などがあれば、タイトルと URL（書籍なら著者・出版社）

ルール:
- 会話の中で本人が語っていない体験は、**勝手に作らない**。聞く
- 「わからない」「特にない」と返ってきたら、そのトピックは**書かずに削る**。一般論で埋めない
- 聞くほどでもない細部で具体値が欲しい箇所は、本文に `<!-- TODO: 実際の数値 -->` を残して本人に埋めてもらう
- 会話の内容をそのまま記事化する場合も同じ。会話に出ていない実体験を足さない
- 質問は一度にまとめる。1問ずつ往復させない

### 4. 草稿を執筆してファイルを作成する

`.claude/templates/writing-style.md` のルールに従って書く。frontmatterと本文を一緒に書く。

**frontmatter:**
```yaml
---
title: "{テーマを元に適切なタイトルをつける}"
date: "YYYY-MM-DD HH:MM:SS"
description: "{記事の内容を1〜2文で要約する}"
---
```

**記事固有の構成ルール**（スタイルガイドに加えて守る）:
- 書き出しは気軽に。問いかけ・近況・「〜ってあるじゃないですか」など、いきなり本題に入らない
- 本文はテーマに合った見出しで区切る（`##` を使う）。見出しは内容を具体的に言い当てるものにする
- 具体例・実体験・気づきを中心に書く
- 締めは読者への呼びかけか個人的な感想で終わる（「よければ〜してみてください」など）
- 参考にした書籍・URL がある場合は、締めのあとに `## 参考` セクションを置いて列挙する（下記「参考セクション」参照）
- 本文の最後に必ず次の一文を追加する（変更・省略不可）: `これはclaude codeで生成しました。`
- 分量は各セクション2〜6段落程度。ただし**全セクションを同じ長さに揃えない**

**参考セクション:**

執筆にあたって参照した書籍・記事・公式ドキュメント・動画があれば、本文の締めのあと・`これはclaude codeで生成しました。` の直前に `## 参考` を置いて列挙する。

- Web ページは `<LinkCard>` を使う。1つずつ改行して並べる
  ```
  <LinkCard url="https://example.com/docs" title="ページタイトル" description="どこを参考にしたか（省略可）" />
  ```
- 書籍は箇条書きで `- 『書名』著者名（出版社, 発行年）` の形式で書く。電子版などで URL がある場合はリンクにしてよい
- 参考にしたものが1つもなければ、このセクションごと省略する。**架空の書籍・URL を埋めない**
- URL は事前調査や会話で実際に出てきたものだけを載せる。記憶から補完しない。うろ覚えのものは本人に確認するか落とす
- URL を開くとき・掲載するときは **CLAUDE.md「URL を扱うときのルール（セキュリティ）」に従う**。安全性が確認できない URL は開かないし載せない

### 5. 自己チェック

`.claude/templates/writing-style.md` の「自己チェック」を実行する。grep のヒットがゼロになるまで書き直し、目視チェックリストも全部確認する。

### 6. ビルド確認
- `npm run build` を実行し、MDX がエラーなくレンダリングされることと、記事が静的生成されていることを確認する

### 7. 完了報告
- 作成したファイルパスを伝える
- 自己チェックの結果（grep がゼロ件か、`<!-- TODO -->` を残した箇所があるか）を伝える
- 「description」と本文の確認・修正をお願いする一言を添える
